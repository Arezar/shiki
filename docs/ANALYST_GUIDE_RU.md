## 1. Краткое описание

Shikimori для Lampa — клиентский плагин-каталог аниме, встроенный в интерфейс медиаплатформы Lampa. Он использует публичные данные Shikimori для просмотра и поиска аниме, предлагает фильтры по характеристикам тайтла, отображает каталог в виде карточек, а при выборе элемента пытается сопоставить аниме с записью фильма или сериала в The Movie Database (TMDB) и открыть штатную страницу Lampa.

Дополнительно плагин обогащает страницу фильма/сериала Lampa сведениями из Shikimori, когда удаётся установить соответствие между TMDB, MyAnimeList и Shikimori. На странице могут появиться рейтинг Shikimori, список фандабберов и список фан-сабберов.

Плагин **не является видеоплеером, торрент-клиентом или самостоятельным каталогом источников просмотра**. Он отвечает за навигацию и метаданные. Фактический просмотр, доступность источников и выбор способа воспроизведения находятся вне его зоны ответственности — в самой Lampa и установленных в ней компонентах/плагинах.

### Ценность, которую сейчас реализует код

- Даёт пользователю Lampa отдельную точку входа в каталог аниме Shikimori.
- Делает поиск и исследование каталога удобнее на телевизоре и с пульта: категории представлены меню, списки — фокусируемыми карточками.
- Позволяет сужать каталог по жанру, формату, статусу выхода, сезону/году, рейтингу, длительности и сортировке.
- Связывает запись каталога Shikimori с привычной карточкой фильма/сериала Lampa, чтобы продолжить пользовательский путь в основном интерфейсе приложения.
- Добавляет профильные для аниме метаданные Shikimori к уже открытой странице TMDB в Lampa.

## 2. Для кого предназначен плагин

Основные предполагаемые группы пользователей:

1. **Пользователи Lampa, которые смотрят аниме.** Им нужен отдельный тематический каталог, не требующий перехода на сайт Shikimori.
2. **Пользователи, которые выбирают, что посмотреть.** Им полезны поиск по названию, жанры, сезон/год, тип аниме, статус выхода и рейтинг.
3. **Пользователи Smart TV и устройств с пультом.** Им важны управление фокусом, последовательные меню Lampa и отсутствие необходимости вводить длинные адреса или работать с OAuth в браузере телевизора.

Это продуктовые гипотезы, выведенные из пользовательских сценариев и интерфейса. В текущем репозитории нет аналитики аудитории, статистики использования или исследований, подтверждающих размер и поведение этих сегментов.

## 3. Пользовательские сценарии

### Сценарий A. Открыть каталог аниме

1. Пользователь открывает главное меню Lampa.
2. Выбирает пункт **Shikimori**.
3. Плагин открывает компонент каталога и загружает первую страницу с сортировкой по рейтингу Shikimori.
4. Пользователь перемещается по карточкам с помощью контроллера/пульта.
5. При достижении конца списка загружается следующая страница.

В одной странице запрашивается до 36 записей. Повторяющиеся ID между страницами не добавляются повторно.

### Сценарий B. Найти конкретное аниме

1. В каталоге пользователь открывает **Filters**.
2. Выбирает пункт поиска по названию.
3. Вводит запрос через штатный механизм ввода Lampa.
4. Применяет фильтры. Каталог открывается с первой страницей и новым набором параметров.
5. Значения фильтров сохраняются в локальном хранилище Lampa и восстанавливаются при следующем открытии.

Если используемая сборка Lampa не предоставляет Lampa.Input.edit, поиск с экранной клавиатуры недоступен; плагин показывает уведомление.

### Сценарий C. Отфильтровать каталог

В меню фильтров доступны следующие параметры:

| Параметр | Реализованные варианты |
|---|---|
| Жанры | Множественный выбор жанров, получаемых из Shikimori API |
| Тип аниме | Любой тип, TV Series, Movie, OVA, ONA, Special, TV Special, Music, PV, CM |
| Статус выхода | Любой статус, анонс (anons), выходит (ongoing), вышло (released) |
| Длительность эпизода | Любая; короткая — до 10 минут (S); средняя — 10–30 минут (D); полная — больше 30 минут (F) |
| Минимальная оценка Shikimori | Любая; 6+, 7+, 8+, 9+ |
| Возрастной рейтинг | Любой; G, PG, PG-13, R, R+ |
| Сезон / год | Десятилетия начиная с 1980-х, вариант «до 1980-х» и сезонные периоды вокруг текущей даты |
| Сортировка | По рейтингу, популярности, дате выхода, названию, числу эпизодов, типу, статусу, сначала новые, сначала старые, случайно |

Жанры загружаются отдельным запросом и в локальном runtime-кэше переиспользуются в течение жизни страницы/плагина. Сброс фильтров очищает выбранные значения и возвращает сортировку по рейтингу.

### Сценарий D. Перейти от аниме к просмотру в Lampa

1. Пользователь выбирает карточку аниме.
2. Плагин получает идентификаторы и названия из записи Shikimori.
3. Если у записи есть MyAnimeList ID, плагин сначала обращается к сервису сопоставления идентификаторов AniMap (arm.haglund.dev), чтобы получить TMDB ID.
4. Если прямое сопоставление не удалось или MAL ID отсутствует, плагин выполняет поиск в TMDB по доступным вариантам названия.
5. Результаты ранжируются по совпадению названия, типу медиа и году выхода.
6. Если найден ровно один кандидат с высоким внутренним баллом совпадения, он открывается автоматически. В остальных случаях пользователю показывается меню выбора до 10 кандидатов.
7. Выбранная сущность открывается через штатную активность full в Lampa.

Сопоставление — эвристическое. Плагин не гарантирует, что у каждого аниме есть корректная запись TMDB. При неоднозначном результате выбор остаётся за пользователем; при отсутствии результатов показывается уведомление.

### Сценарий E. Посмотреть дополнительные сведения на странице Lampa

Когда Lampa сообщает о завершении загрузки страницы full и у неё есть TMDB ID, плагин:

1. Запрашивает через AniMap соответствующий MyAnimeList ID.
2. По этому ID получает запись аниме из публичного Shikimori API.
3. В правой части описания добавляет поля Fan Dubbers и Fan Subbers, если данные присутствуют.
4. Добавляет оценку Shikimori в строку рейтингов, если рейтинг присутствует.

Дополнение не блокирует штатную страницу Lampa: при неудаче сопоставления или запроса плагин пишет предупреждение в консоль и не отображает соответствующие дополнительные данные.

## 5. Что намеренно не входит в текущий функционал

В ранних версиях существовала экспериментальная работа с аккаунтом Shikimori. Она полностью удалена из актуальной версии. Сейчас нет:

- OAuth-авторизации и подключения аккаунта Shikimori;
- хранения и обновления access/refresh tokens;
- загрузки профиля пользователя или персонального списка user_rates;
- экранов «мой список» и фильтров личного списка;
- изменения статуса просмотра, оценки пользователя или количества просмотренных эпизодов;
- синхронизации прогресса просмотра с аккаунтом Shikimori;
- личных бейджей статуса на карточках каталога;
- собственной локальной закладки/watchlist плагина.

При старте текущий код очищает legacy-ключи, оставшиеся от прежней OAuth-версии: lme_shikimori_account_v1 и lme_shikimori_oauth_state. Для первого ключа записывается пустой объект, для второго — пустая строка. Это миграционная очистка старых данных, а не активная авторизация.

## 6. Архитектура и устройство кода

Проект реализован как один клиентский JavaScript-файл — Shikimori.js. Код обёрнут в IIFE и использует API среды Lampa. В репозитории также находится smoke-тест tests/smoke.cjs и workflow проверки .github/workflows/validate.yml.

### Основные логические блоки

- **NetworkManager** — тонкая обёртка над $.ajax: GET/POST JSON, таймауты, отслеживание активных запросов и отмена запросов при закрытии/перезапуске компонента. Намеренная отмена не трактуется как ошибка сети.
- **main(params, ...)** — формирует GraphQL-запрос Shikimori для каталога. Запрашивает 36 элементов, номер страницы, сортировку и переданные фильтры.
- **search(animeData, network)** — выполняет сопоставление записи Shikimori с TMDB, сначала по MAL ID через AniMap, затем по названию.
- **Card** — создаёт карточку каталога. При наличии Lampa Maker и app_digital не ниже 300 использует нативную карточку Lampa; иначе использует fallback-шаблон плагина.
- **Component$1** — компонент LMEShikimori: меню, фильтры, загрузка страниц, карточки, управление фокусом и очистка ресурсов.
- **Component** — подписка на события full и activity, добавляющая сведения Shikimori на страницы фильмов/сериалов Lampa.
- **startPlugin()** — регистрирует компонент, manifest, шаблон карточки, CSS и пункт меню.

### Используемые API Lampa

Плагин опирается на доступность следующих интерфейсов Lampa (набор и детали могут отличаться между сборками):

- Lampa.Component.add и manifest.component для регистрации компонента;
- Lampa.Activity.push для открытия каталога и full-страницы;
- Lampa.Listener.follow/remove для событий приложения, full и activity;
- Lampa.Storage.get/set/field для локальных настроек и языка;
- Lampa.Scroll, Lampa.Select, Lampa.Input.edit для списка, меню и ввода;
- Lampa.Maker.make, Lampa.Template, Lampa.Controller и Lampa.Empty для карточек, шаблонов, управления фокусом и пустого состояния.

Для Lampa 3.x предусмотрен путь с нативной карточкой через Lampa.Maker. Для более старого/несовместимого окружения предусмотрен собственный HTML-шаблон.

## 7. Внешние сервисы и потоки данных

Плагин работает непосредственно из клиентской среды Lampa. Отдельный сервер проекта, backend, собственная база данных или серверный OAuth-посредник в репозитории отсутствуют.

| Сервис | Назначение | Используемые обращения |
|---|---|---|
| Shikimori | Основные публичные данные каталога | POST https://shikimori.one/api/graphql; GET https://shikimori.one/api/genres |
| Shikimori | Дополнительные сведения по аниме | GET https://shikimori.one/api/animes/{malId} |
| AniMap (arm.haglund.dev) | Сопоставление идентификаторов TMDB и MyAnimeList | GET /api/v2/ids?source=myanimelist&id=...; GET /api/v2/themoviedb?id=... |
| TMDB | Поиск фильмов/сериалов и получение полной карточки | GET /3/search/multi и GET /3/{movie или tv}/{id} |
| Lampa TMDB proxy (опционально) | Альтернативный маршрут запросов TMDB | Используется, если в Lampa включён proxy_tmdb и задан cub_domain |

Поток каталога: Lampa → Shikimori GraphQL → карточки каталога → AniMap/TMDB при выборе → штатная full-страница Lampa.

Поток обогащения страницы: событие full в Lampa → AniMap (TMDB → MAL) → Shikimori REST (MAL ID) → добавление рейтинга и сведений о фандабе/сабах в DOM full-страницы.

### Какие данные передаются во внешние сервисы

- В Shikimori передаются поисковая строка и выбранные параметры публичного каталога (тип, статус, жанры, сезон, оценка, рейтинг, длительность, страница и сортировка).
- В AniMap и TMDB передаются идентификаторы и/или варианты названий выбранного аниме для поиска соответствия.
- Для дополнительного обогащения full-страницы передаётся TMDB ID, а затем используется найденный MAL ID.

Плагин не запрашивает данные аккаунта пользователя и не передаёт в Shikimori его список просмотров, так как соответствующая функциональность удалена. В просмотренном исходнике нет собственного backend endpoint или отдельного механизма продуктовой телеметрии. При этом сетевые запросы к внешним сервисам выполняются с устройства пользователя; сами сервисы и инфраструктура Lampa могут получать обычные технические метаданные сетевого соединения.

## 8. Хранение данных и приватность

### Постоянное локальное хранилище

| Ключ | Содержимое | Назначение |
|---|---|---|
| lme_shikimori_filters_v1 | Объект с активными фильтрами и поисковой строкой | Восстановление предпочтений каталога |
| lme_shikimori_account_v1 | В актуальном коде принудительно очищается до {} | Удаление данных от старой OAuth-версии |
| lme_shikimori_oauth_state | В актуальном коде принудительно очищается до пустой строки | Удаление незавершённого OAuth-состояния старой версии |

### Runtime-хранилище

В оперативной памяти процесса используются кэш жанров и кэш найденных соответствий TMDB. Это не облачная синхронизация и не постоянная база; данные могут исчезнуть при перезапуске приложения.

### Выводы для оценки приватности

- В актуальном функционале нет входа в личный аккаунт Shikimori.
- Плагин не ведёт собственный список просмотров и не синхронизирует его.
- Поисковые фразы и параметры каталога передаются Shikimori; названия и идентификаторы выбранных произведений могут отправляться AniMap и TMDB.
- Локально сохраняются только настройки фильтрации, а также выполняется очистка устаревших ключей авторизации.
- В исходнике нет отдельного проекта backend или собственного endpoint аналитики. Это вывод по текущему репозиторию, а не аудит всего приложения Lampa или внешних сервисов.

## 9. Технические ограничения и риски

### Зависимость от внешних API

Каталог зависит от доступности и совместимости Shikimori GraphQL/REST API. Функция перехода к карточке Lampa дополнительно зависит от AniMap и TMDB. Отказ любого из сервисов может привести к пустому каталогу, отсутствию дополнительных метаданных или невозможности найти соответствие.

### Неоднозначность идентификации

Сопоставление по MAL ID обычно предпочтительнее поиска по названию, но внешний mapping может отсутствовать. Резервный поиск сравнивает нормализованные варианты названия, тип медиа и год. Это эвристика, не гарантированная идентификация. Для части тайтлов потребуется ручной выбор, а некоторые названия могут не найтись совсем.

### Совместимость Lampa / Smart TV

Код предусматривает нативные карточки Lampa 3.x и fallback-шаблон, а также использует системные меню/скролл/контроллер. Однако Node smoke-тесты не заменяют проверку на реальных телевизорах, пультах, WebView и конкретных сборках Lampa. В текущем репозитории нет автоматизированного e2e-покрытия для таких сред.

### Клиентская интеграция TMDB

В исходном JavaScript присутствует API key TMDB, используемый клиентскими запросами. Такой ключ доступен пользователю, который может прочитать файл плагина или сетевые запросы, поэтому его нельзя считать секретом. Для публичного распространения следует отдельно оценить условия использования ключа, ограничения/квоты и возможность его ротации или использования контролируемого proxy. Документ не публикует значение ключа намеренно.

### Отсутствие офлайн-режима

Каталог и сопоставление требуют сетевых запросов. Постоянного каталожного кэша или режима офлайн-просмотра в текущем коде нет. Сохранение фильтров не означает сохранения результатов каталога.

## 10. Тестирование и контроль качества

В репозитории присутствует tests/smoke.cjs. Он запускает код в Node VM с заглушками API Lampa и jQuery/AJAX. Текущий набор содержит 9 групп проверок:

1. Корректная отмена сетевого запроса без запуска error fallback.
2. Формирование GraphQL variables, поддержка фильтров и обработка GraphQL-ошибки.
3. Работа нативной карточки, namespacing Shikimori ID и отсутствие личных/чужих card modules.
4. Восстановление фильтров и неизменность параметров между страницами.
5. Сброс фильтров и корректное снятие отметок выбора.
6. Постраничная загрузка, блокировка параллельного запроса, дедупликация ID и отмена запроса при destroy.
7. Отображение пустого состояния при восстановлении страницы без результатов.
8. Безопасность fallback-карточки при HTML-подобном названии и отсутствие локального watchlist.
9. Отсутствие OAuth/account-функций и очистка legacy storage.

GitHub Actions workflow .github/workflows/validate.yml использует Node.js 20 и выполняет:

- node --check Shikimori.js
- node tests/smoke.cjs

Эти проверки подтверждают синтаксис и отдельные сценарии бизнес-логики в тестовой среде. Они **не подтверждают** реальную доступность сторонних API, корректность всех соответствий AniMap/TMDB, работу на каждой версии Lampa или стабильность на конкретном телевизоре.

## 11. Что в проекте есть и чего нет с точки зрения продукта

**Фактически есть:** тематический каталог аниме, поиск, восемь групп фильтрации, сортировка, постраничная загрузка, карточки для Lampa, переход к полной странице через сопоставление, дополнительный рейтинг и сведения о командах озвучки/субтитров.

**Фактически нет:** авторизации Shikimori, персонального списка, статусов просмотра, синхронизации прогресса, пользовательских оценок, собственной системы рекомендаций, собственного проигрывателя, собственной базы контента, backend, телеметрии и e2e-проверки устройств.

Для продуктовой оценки важно разделять две задачи:
- **Discovery / выбор контента:** это основная функция данного плагина.
- **Playback / управление просмотром:** это ответственность Lampa и её других компонентов; плагин только передаёт пользователя к полной карточке найденного объекта.

## 12. Вопросы, которые аналитику полезно оценить

1. Решает ли отдельный каталог Shikimori реальную проблему обнаружения аниме внутри Lampa или аналогичный путь уже достаточно хорошо покрывается стандартными каталогами?
2. Насколько часто пользователю удаётся пройти путь от карточки Shikimori до корректной full-страницы TMDB? Какова доля автоматических совпадений, ручных выборов и неудачных поисков?
3. Какие фильтры действительно помогают выбирать аниме, а какие усложняют TV-интерфейс?
4. Насколько понятна пользователю разница между рейтингом Shikimori и рейтингом TMDB/Lampa?
5. Насколько ценны сведения о фандабберах и фан-сабберах на full-странице?
6. Достаточны ли текущие сценарии для пользователя Smart TV с пультом и ограниченным вводом текста?
7. Какой уровень зависимости от сторонних API и mapping-сервисов приемлем для продукта?
8. Стоит ли в будущем добавлять аккуратную телеметрию (только при понятной цели, прозрачном уведомлении и минимизации данных), чтобы измерять успешность каталожного пути? Сейчас встроенной продуктовой аналитики нет.

### Рекомендуемые продуктовые метрики для отдельного исследования

В текущей реализации эти метрики не собираются. Их можно измерять в модерируемом тестировании или внедрить позже с отдельным решением по приватности:

- доля открытий каталога, закончившихся выбором карточки;
- доля выбора, завершившегося корректным открытием full-страницы;
- доля автоматических сопоставлений и доля случаев, требующих ручного выбора;
- доля неудачных сопоставлений;
- время от открытия каталога до выбора тайтла;
- частота применения отдельных фильтров;
- успешность управления с пульта на различных устройствах.

## 14. Итог для аналитической оценки

Текущий проект лучше оценивать как **лёгкий discovery-плагин для аниме внутри Lampa**, который использует Shikimori как источник каталожной информации и TMDB/AniMap как мост к существующему пути просмотра в Lampa.

Его главная продуктовая задача — сократить путь от интереса к аниме до открытия соответствующей карточки в Lampa, дать тематические фильтры и добавить контекст Shikimori. Он не пытается управлять пользовательской коллекцией и не заменяет систему воспроизведения Lampa.

Ключевые предметы оценки: реальная востребованность отдельного каталога, качество сопоставления Shikimori ↔ MAL ↔ TMDB, удобство TV-навигации, устойчивость внешних API, совместимость с разными сборками Lampa и оправданность текущего набора фильтров. Для выводов о стабильности на Smart TV потребуется отдельное тестирование в реальной среде — имеющиеся smoke-тесты этого не заменяют.
