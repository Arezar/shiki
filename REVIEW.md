# Code Review: Shikimori.js (баги)

Обзор существующего кода плагина без изменения исходника.
Проверено: весь файл (1383 строки), `node --check`, `node tests/smoke.cjs` (PASS, 13 групп),
ESLint (no-dupe-keys / no-unreachable / no-fallthrough и т.п. — 0 ошибок), а также сверка
с реальным исходником Lampa (`yumata/lampa`, `app.min.js`) и живыми ответами Shikimori REST API.

## Критичные

### 1. Фильтр «Год выпуска»: коды `1990x` / `1980x` отклоняются API — ✅ исправлено
**Строки:** `Shikimori.js` `createYearItems` (генерация кодов), отправка `$season` в `main()`.

`createYearItems` для десятилетий < 2000 генерировал коды вида `1990x`, `1980x`, а Shikimori
принимает только формат `199x` / `198x` (регэксп `\d{3}x` в `Animes::Filters::BySeason`;
невалидный сезон поднимает `InvalidParameterError` → `response.errors` → каталог не грузится,
«Повторить» тоже безуспешен). Проверено вживую:

```
GET /api/animes?season=1990x      → [ "Invalid season value \"1990x\"" ]  ✗ ошибка
GET /api/animes?season=2010_2019  → [ { "id": 21561, ... } ]             ✓ работает
GET /api/animes?season=199x       → [ { "id": 617, ... } ]               ✓ работает (1993)
GET /api/animes?season=ancient    → [ { "id": 7528, ... } ]              ✓ работает (1952)
GET /api/animes?season=fall_2026  → [ { "id": 65054, ... } ]             ✓ работает (дефолт)
```

Пункты `2020_2029`, `2010_2019`, `2000_2009`, `ancient` — валидны (формат `YYYY_YYYY`/`ancient`
разрешён тем же фильтром; GraphQL-скаляр `SeasonString` наследует `GraphQL::Types::String` без
дополнительной валидации — решает тот же `BySeason`, что и REST).

**Влияние:** выбор «1990-е»/«1980-е» + «Показать результаты» (или сортировка/поиск — `persistFilters`)
кладёт невалидный код в `lme_shikimori_filters_v1`; **storage перебивает дефолты при каждом
открытии**, поэтому каталог остаётся сломанным до сброса фильтров. Каталог падает с Noty
«Не удалось загрузить каталог: Invalid season value "1990x"» + кнопка «Повторить».

**Фикс (в этой ветке):** коды десятилетий < 2000 → `Math.floor(decade/10) + 'x'` (`199x`, `198x`);
плюс `sanitizeFilterState()` в `create()` — невалидные `seasons`/`sort` из storage (в т.ч. из
восстановленной активности Lampa) сбрасываются на текущий сезон/`popularity`. Регрессионные тесты
в `tests/smoke.cjs`: коды в меню года + отравленный storage `{seasons:'1990x'}` (на неисправленном
коде падает с `actual: '1990x'`).

### 2. Фильтры «Год выпуска» и «Сезон» — ❌ не баг (вердикт автора)
Автор: год и сезон — один параметр `season` в Shikimori («2026» ⊃ «зима 2026»), взаимное
исключение выбора — корректная семантика. Спорные мелочи (двойной учёт в `activeFilterCount`
при одновременно сохранённых обоих слагах) остаются как низкоприоритетное наблюдение, не дефект.

## Средние

### 3. Сортировка `ranked` не попадает в меню сортировок
**Строки:** `defaultFilterState.sort` `:526` (`'popularity'`), `restoreFilterSelection` `:645`
(fallback `'ranked'`).

Если в storage уже лежит `sort: 'ranked'` (старые версии писали `'ranked'` — см. `tests/smoke.cjs:642`),
после реставрации фильтры применяются с `ranked`, а `selectCurrentSortItem` не находит пункт с
`currentSort = 'ranked'` → в меню подсвечено/выбрано «По популярности», фактический запрос другой.
Плюс несоответствие двух источников истины: fallback `ranked` против дефолта `popularity`.

**Фикс:** привести `restoreFilterSelection` к `'popularity'` или добавить пункт `ranked` в `createSortItems`.

### 4. Двойное HTML-экранирование — пользователь видит `&amp;` в заголовке и пунктах
**Строки:** `escapeHtml` `:28–32`, `loadGenres` `:453`, `showCandidates` `:266`,
`applyFilters` → `params.title` `:881–882`.

`escapeHtml` применяется к тексту, который дальше вставляется как **текст**, а не как HTML:

* `Head.title` в Lampa — это `$('.head__title').text(title)` (`app.min.js:20168`), т.е. `.text()`
  экранирует сам; заголовок вида `Фантастика & приключения` отобразится как `Фантастика &amp; приключения`.
* заголовок меню `Select` (`select__title`) вставляется как HTML без декодирования (`app.min.js:8083`) —
  экранирование избыточно и видимо.
* `localeCompare` в `sortItems`/`loadGenres` сортирует по **уже экранированным** строкам —
  порядок пунктов с спецсимволами может отличаться от алфавитного.

**Фикс:** убрать `escapeHtml` там, где значение уходит в `.text()`/plain-текст; оставить только для
шаблона `LMEShikimori-Card` (там вставка через HTML — экранирование корректно).

### 5. `applyFilters` всегда делает `Activity.push` — слайды копятся, фильтры сбрасываются на `back()`
**Строки:** `applyFilters` `:880–889`, `destroy` `:930–946`.

Каждый выбор в меню фильтров создаёт новый слайд Activity. Проверено по Lampa
(`Activity.push` → `start$4` → новый `ActivitySlide`, старый слайд уничтожается только через
`Activity.backward()` → `curent.activity.destroy()`):

* стек слайдов растёт → для выхода из каталога после N применений фильтров нужно N нажатий «назад»;
* `destroy()` старого слайда сбрасывает `FILTERS_STORAGE_KEY` к `{seasons: [], sort: 'popularity'}`
  — т.е. любой «назад» через каталог затирает только что применённые фильтры в storage
  (UI текущего слайда это ещё не трогает, но после повторного захода в каталог фильтры потеряны).

**Фикс:** вместо `Activity.push` обновлять текущий слайд (`Activity.replace` / ре-рендер контента)
или сбрасывать storage только если слайд покидается с неизменёнными фильтрами.

### 6. `loadPage`: `$.extend({}, filterParams, object, {page})` — устаревший `object` перекрывает фильтры
**Строки:** `:1074–1075`.

Порядок `extend` такой, что `object` (поля слайда Activity: `search`, `genres`, `year`, `order`…)
**перекрывает** актуальный `filterState` из `filterParams`. Если слайд был создан с этими полями
(например, `search` из меню или `year`), они всегда побеждают — изменённые в меню фильтры не применяются.
Плюс прямая мутация `object.page = query.page` (`:1075`) портит исходный объект слайда.

**Фикс:** `$.extend({}, object, filterParams, {page: query.page})` — приоритет фильтрам; `page` не писать в `object`.

### 7. `runtimeCache.tmdb` не учитывает язык — поиск по TMDB после смены локали отдаёт старые данные
**Строки:** `API.search` `:297–305` (ключ `runtimeCache['tmdb_' + id]` без языка), `requestGet` `:78`.

`getSearch(name, locale)` зависит от `Lampa.Lang.current`, но ключ кэша — только id. После смены
языка в настройках Lampa повторный поиск того же названия вернёт результат, закэшированный на прежнем языке.

**Фикс:** включать язык в ключ (`'tmdb_' + id + '_' + Lampa.Lang.current`).

### 8. `getMappedTmdb`: поле `kind` не существует в ответе arm.haglund — маппинг всегда проваливается
**Строки:** `:412–414`.

Проверено на живом API `arm.haglund.dev/api/v2/ids`:

```json
{"myanimelist": 1, "themoviedb": 30991, "media": "TV", "thetvdb": 76885, ...}
```

Тип называется полем `media` (со значениями `TV` / `Movie`), а не `kind`. Чтение
`mapping.animeData.kind` даёт `undefined` → условие `!= 'TV'` всегда истинно → `tmdb_type` всегда
`'movie'` → для сериалов запрос идёт в movie-эндпоинт TMDB с id TV-сериала → 404 →
`mappedTmdb = null` → каждый раз уходит в медленный fallback-поиск с таймаутом.

**Фикс:** читать `mapping.animeData.media` и сравнивать с `'Movie'` (плюс страховка на `kind`).
Попутно: `if (!mapping) return null` (`:410`) бессмысленно после `JSON.parse` — исключение
перехватится в `API.search` (`:292`).

### 9. `main()`: любой `response.errors` считается фатальным
**Строки:** `:166–168`.

GraphQL может вернуть `data` вместе с `errors` (частичные данные). Сейчас наличие `errors`
полностью отменяет результат, хотя непустые `data.animes` валидны. Пользователь видит ошибку там,
где данные были получены.

**Фикс:** обрабатывать `errors` только когда `!response.data || !response.data.animes`.

### 10. `NetworkManager`: abort не доходит до обработчика, `errorDecode` получает не тот аргумент
**Строки:** `:121–147`.

* при `status === 'abort'` колбэк `error` не вызывается вообще (`:129–131`) — если отмена не
  связана с закрытием экрана (например, `xhr.abort()` извне), `loading` навсегда остаётся `true`,
  спиннер/`requestLoading` не снимается, повторные запросы блокируются;
* `errorDecode(error, error && error.statusText)` (`:131`) — второй аргумент по спецификации
  `errorDecode(params, message)` это **текст ошибки**, а не `xhr.statusText`; на практике приходит
  `'error'` → ни timeout, ни abort не распознаются, показывается дефолтное сообщение.

**Фикс:** в ветке abort вызывать `error('abort')`; передавать в `errorDecode` `error.type` и
текст вида `error.status + ': ' + (error.statusText || 'error')`.

### 11. Циклы и флаги повторных запросов
**Строки:** `showRetry` `:890–904`, `onEnd` `:1014–1016`, `loadGenres` `:490–502`, `reloadCurrent` `:1033`.

* при ошибке страницы >1 (`showRetry`) `hasMore` не сбрасывается → после «повторить» скролл
  может снова уйти в `onEnd` и зациклить `loadPage` (повторная ошибка → снова retry → …);
  фикс: `hasMore = false` в `showRetry`, `hasMore = true` только при успехе;
* `loadGenres` ретраит мгновенно (`setTimeout 0`) — два запроса подряд без задержки;
  `genresLoaded = true` ставится и в ветке ошибки (`:497`) — повторной попытки при следующем
  открытии фильтров не будет;
* `reloadCurrent()` (`:1033`) — **мёртвый код**: нигде не вызывается (проверено grep и ESLint
  `no-unused-vars: 1033`); если будет вызван — не сбрасывает `object.page`, т.е. перезагрузит
  не текущую страницу, а ту, что в `object.page`.

## Мелкие

### 12. `Card`: ветка native при исключении остаётся «сломанной», хуки не отписываются
**Строки:** `:368–395`.

`this.native = true` ставится внутри `try` **после** `Lampa.Maker.make` (`:368`): если `make`
выбросил, `element` остался `undefined` → `card` не отрисуется, `Lampa.Noty.show` покажет ошибку,
но нативная ветка уже активна. В `destroy()` нативная ветка не снимает подписки
`onCreate/onFocus/onEnter` (`:387–388`) — при отсутствии `element` они не снимутся, возможна
утечка обработчиков.

### 13. `main()` игнорирует `params.limit`
**Строки:** `:147–159`, `:162–165`.

`buildQuery` использует `params.limit`, но `main` жёстко вставляет `limit: 24` в variables —
переданный `limit` не применяется.

### 14. `rankCandidate` пересчитывается внутри компаратора + дублирование логики
**Строки:** `:269–275`.

`sort` вызывает `rankCandidate` 2× на сравнение → O(n log n) вызовов чистой функции; при 20+ кандидатах
лишняя работа. Плюс `rankCandidate` дублирует `cleanName` + `normalizeMatchTitle`, а
`normalizeTitle` (`:37`) — ещё один вариант нормализации с другой логикой: три почти одинаковых
функции в одном файле (риск расхождения при правках).

### 15. `this.empty()` подменяет `this.start` без восстановления
**Строки:** `:1294–1299`.

`start` заменяется на пустую функцию (`:1373` перезаписывает и `controller`); после показа
«нет результатов» исходный `start` не восстанавливается — повторный `start()` слайда
(возврат на экран) не поднимет контроллер.

### 16. `Lampa.Manifest.plugins` перезаписывается объектом вместо массива
**Строки:** `:1369–1374`.

Setter в Lampa (`object$2.plugins`) принимает объект с `typeof plugin.type === 'string'`, поэтому
регистрация проходит, но значение поля меняется с массива (как в `lampa.js:2866`, элементы вида
`{url, type: 'link'}`) на один объект. Код Lampa/плагинов, ожидающий массив (`.map`, `.forEach`),
после загрузки Shikimori-плагина получит объект.

**Фикс:** добавлять в массив: `Lampa.Manifest.plugins = Lampa.Manifest.plugins.concat([...])`
(сверить, что getter отдаёт копию/живой массив) либо использовать штатный API регистрации плагинов.

### 17. Прочее (стиль/производительность, не влияет на работу)
* `showCandidates` (`:262–264`) — сортировка с дедупликацией каждый раз, `candidates` хранит
  оригинальные (не отфильтрованные) значения — `rank` ищет по исходному массиву (работает, но хрупко).
* `filterState.genres[0].id` (`:1073`) — если в storage попал элемент без `id`,
  `genre: undefined` молча исключится из запроса.
* `imageUrlValue` использует `.indexOf('|')` вместо `split` — корректно, но неочевидно (`:35`).
* ESLint `no-param-reassign`: `:458–459` (`loadCards` мутирует `data`/`handlers`), `:547`
  (`Component$1` мутирует `object`) — источник неочевидных побочных эффектов при рефакторинге.

* `getSeason` (`:35–53`): `Math.floor(month / 3)` + `current_year` — корректно.
* `GET /api/animes/:id` по id из `object.id` — рабочий сценарий (id Shikimori вида `/animes/52991-...`).
* `Select.onBack` в Lampa вызывается только при закрытии (`app.min.js:8255`) — «Back из меню фильтра
  возвращает в группу» реализовано корректно, `Controller.toggle(previousController)` — штатно.
* `Scroll.minus` (`:871–874`) + `onEnd` (`:1010`) — бесконечная прокрутка без потери позиции работает.
* `Input.edit` принимает `value/title/free/nosave/password` (`app.min.js:55354`) — вызовы валидны.
* `Lampa.Noty.show` — просто `.html(text)` (`app.min.js:4058`), строки вида `"«X» уже добавлена"` безопасны.
* Регистрация в `Lampa.Manifest.plugins` с `{url, title, type: 'plugin'}` — setter принимает
  (`app.min.js:2862–2885`), сама по себе не падает (см. п.16 про тип значения).
* `Card`-хуки `onCreate/onFocus/onEnter/onDestroy` — существуют в Lampa (`app.min.js:15760+`).
* Тест `tests/smoke.cjs` проходит (13 групп), `node --check` — чисто; CI воспроизводит обе проверки.
