# Подключение аккаунта Shikimori

Плагин может читать список аниме авторизованного пользователя и изменять его записи: статус просмотра, оценку и число просмотренных эпизодов.

## 1. Создайте OAuth-приложение

Откройте [Shikimori → OAuth Applications](https://shikimori.one/oauth/applications) и создайте приложение для Lampa.

В настройках приложения:
- задайте имя, например **Lampa Shikimori**;
- укажите Redirect URI, который будете использовать в плагине;
- включите scope **user_rates**, если он доступен для приложения.

Redirect URI в плагине должен в точности совпадать с URI в настройках OAuth-приложения. Плагин не предполагает конкретный домен или callback-хост пользователя.

## 2. Укажите параметры в Lampa

Откройте каталог Shikimori → **Shikimori account** → **Настроить OAuth-приложение**. Введите:
- Client ID;
- Client Secret;
- Redirect URI.

Параметры и токены записываются в локальное хранилище Lampa на текущем устройстве. Отключение аккаунта удаляет сохранённые токены и локальную привязку; настройки OAuth-приложения остаются на устройстве для повторного входа. Чтобы отозвать разрешение приложения на стороне Shikimori, откройте страницу [OAuth Applications](https://shikimori.one/oauth/applications).

## 3. Авторизуйтесь

Выберите **Подключить аккаунт Shikimori**. Плагин откроет страницу авторизации. После разрешения доступа скопируйте полный URL, на который Shikimori перенаправил браузер (в нём должны присутствовать **code** и **state**), и вставьте его в Lampa.

После успешного входа откроется ваш список аниме. Доступный список можно фильтровать по статусам: смотрю, запланировано, просмотрено, отложено, брошено и пересматриваю.

### Ограничения WebView / Smart TV

OAuth callback в плагине вводится вручную: после разрешения доступа вставьте полный redirect URL с `code` и `state`. Вход через сокращённый OOB-код без `state` не поддерживается. Если браузер не открывается автоматически, откройте адрес авторизации вручную на телефоне или компьютере, завершите вход там и скопируйте итоговый URL в Lampa.

Shikimori API документирует обязательный `User-Agent` с именем OAuth-приложения. Браузерный JavaScript не может выставлять этот заголовок самостоятельно, а некоторые WebView/браузеры также блокируют прямые API-запросы из-за CORS. Поэтому прямой запрос из Lampa может работать не во всех сборках и сетевых окружениях. Если API возвращает CORS/сетевую ошибку либо требует корректный `User-Agent`, надёжное решение — серверный proxy, который добавляет заголовок приложения и проксирует OAuth/API-запросы. Плагин не пытается подменять запрещённый браузером заголовок и не обещает совместимость с каждым WebView.

## 4. Изменение списка

В каталоге или в личном списке удерживайте карточку, затем в штатном контекстном меню Lampa выберите **Изменить запись в Shikimori**:
- выберите статус просмотра;
- задайте оценку от 0 до 10;
- измените количество просмотренных эпизодов;
- удалите запись из списка.

Записи создаются и обновляются через Shikimori API v2. При истечении access token плагин пытается автоматически получить новый через refresh token.

## Важное замечание о безопасности

Официальный Shikimori OAuth flow требует **client_secret** и для обмена authorization code, и для обновления токена. Поэтому в чисто клиентском плагине секрет невозможно надёжно скрыть: пользователь, имеющий доступ к хранилищу Lampa на устройстве, потенциально сможет его прочитать.

Не используйте один общий Client Secret в публично распространяемом файле плагина. Для централизованной публичной интеграции нужен отдельный серверный OAuth-посредник, который хранит секрет на сервере. Текущая реализация предназначена для настройки собственного OAuth-приложения пользователем.
